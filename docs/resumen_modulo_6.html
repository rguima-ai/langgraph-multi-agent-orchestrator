Un sistema multi-agente divide un problema grande entre especialistas. Un Supervisor observa el progreso, decide quién trabaja después y finaliza únicamente cuando la respuesta cumple la calidad esperada.

1. La idea central

01

Dividir

Separar investigación, cálculo y redacción para que cada agente tenga una responsabilidad clara.

02

Coordinar

El Supervisor mira el estado completo y elige el próximo nodo; no hace el trabajo del especialista.

03

Validar

Cada resultado entra al estado solamente después de cumplir un contrato de Pydantic.

04

Finalizar

El flujo llega a END cuando existe evidencia, análisis e informe final suficientes.

4. El estado compartido

El estado es la memoria de trabajo del grafo. No es una variable global que todos modifican libremente: cada nodo devuelve una actualización y LangGraph la integra.

class AgentState(MessagesState, total=False):
    request: str
    research_output: dict | None
    analysis_output: dict | None
    final_report: dict | None
    next_agent: Literal["researcher", "analyst", "synthesizer", "FINISH"]
    step_count: int
    max_steps: int

Aislamiento de escritura: el Investigador escribe research_output; el Analista escribe analysis_output; Síntesis escribe final_report. Así se reducen choques y sobrescrituras.

5. Por qué usamos asyncio

Una llamada a un LLM o a una búsqueda pasa mucho tiempo esperando la red. Con async def y await, Python puede atender otras tareas durante esa espera.

6. Pydantic como contrato

El LLM puede devolver texto incompleto o un número fuera de rango. Pydantic convierte las expectativas en reglas ejecutables.

class ResearchArtifact(BaseModel):
    query: str
    findings: list[ResearchFinding]
    summary: str
    confidence: float = Field(ge=0.0, le=1.0)

Si confidence vale 1.7, el artefacto se rechaza. El error se guarda y el Supervisor puede decidir un reintento.

7. Qué hace esta pre-entrega

  1. Recibe una solicitud sobre el mercado solar.
  2. El Supervisor llama al Investigador.
  3. El Investigador usa una búsqueda simulada y devuelve 2023 = 120 y 2024 = 144.
  4. El Supervisor llama al Analista.
  5. El Analista calcula ((144 - 120) / 120) × 100 = 20%.
  6. El Supervisor llama a Síntesis.
  7. Síntesis produce un informe con fuentes, recomendación y limitaciones.
  8. El Supervisor comprueba la rúbrica y elige FINISH.

La traza JSON muestra las decisiones observables, no el razonamiento privado del modelo.

8. Errores comunes

Supervisor infinito

Se evita con max_steps y recursion_limit.

Supervisor trabajador

El Supervisor coordina. Investigar o calcular rompe la separación de responsabilidades.

Estado mutable global

Los nodos deben devolver actualizaciones; no compartir una lista global con .append().

Output sin validar

Todo artefacto del LLM debe comprobarse antes de entrar al estado.

Contexto excesivo

Cada especialista recibe solamente la información necesaria para su tarea.

Error de red sin capturar

Timeouts y rate limits deben convertirse en errores controlados para permitir recuperación.

9. Glosario rápido

NodoUna función del grafo: Supervisor, Investigador, Analista o Síntesis.
AristaLa conexión que determina hacia dónde puede continuar el flujo.
Arista condicionalUna conexión cuyo destino depende del estado.
EstadoLa información compartida y acumulada durante la ejecución.
ReducerLa regla usada para combinar una actualización con el estado anterior.
ToolUna función externa que el agente puede solicitar con parámetros estructurados.
ArtefactoLa salida validada y reutilizable de un especialista.
RúbricaLos criterios de calidad que usa el Supervisor para aceptar o pedir correcciones.
